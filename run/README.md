# Run Scripts

This directory contains two groups of runners:

- Original batch helpers from the GPS-SLAM release.
- Research runners added for MultiEngine SDF submaps, Gaussian submaps, quality
  validation, and TUM loop-closure experiments.

The runners generate YAML configs and launch `slam_trainer`; they do not change
the runtime implementation directly.

## Original Helpers

| Script | Purpose |
| --- | --- |
| `train.py` | Walk a config directory and run `build/slam_trainer` on each YAML file. |
| `eval.py` | Walk a config directory and run evaluation commands. |
| `read_results.py` | Parse `time_log.txt` and metric JSON outputs into a summary CSV. |
| `run.sh` | Original train/eval/read-results wrapper. |

## Canonical Research Runners

| Script | Purpose |
| --- | --- |
| `hybrid_validation.py` | Main Replica smoke, quality, and regression runner. Generates matched configs for BasicEngine, unified Gaussian, MultiEngine SDF, and hybrid Gaussian-submap profiles. |
| `tum_loop_validation.py` | Main TUM RGB-D runner for online loop-closure baselines, dry-run, solve-only, and apply modes. |
| `render_policy_sweep.py` | Eval-only sweep for render-selection and overlap-compositor policies on an existing checkpoint. |
| `hybrid_training_sweep.py` | Small bounded sweep for Gaussian-submap training and handoff policies. |

## Cleanup And Archival

| Script | Purpose |
| --- | --- |
| `cleanup_experiments.py` | Archive evidence from local legacy runs, then prune bulky artifacts after review. |
| `prune_run_artifacts.py` | Archive evidence and prune bulky artifacts from external-drive run roots. |

Both cleanup scripts are conservative by default. Review their dry-run output
before passing `--execute`.

## Legacy/Exploratory Runners

| Script | Purpose |
| --- | --- |
| `experiments_runner.py` | Early FPS/ATE config sweep runner. Kept for traceability, but not used for current headline results. |
| `batch_experiments.sh` | Shell wrapper for the early experiment sweeps. Kept for traceability. |

For current claims, prefer summary rows generated by `hybrid_validation.py` and
`tum_loop_validation.py`, and verify `input_dir`, `gt_dir`, binary hash profile,
and TSDF hash profile in the summary CSV before comparing runs.

## Locked Headline Runs

Follow [`../BENCHMARK_PROTOCOL.md`](../BENCHMARK_PROTOCOL.md). Passing
`--benchmark-protocol` makes the runners reject confounded comparisons and
write `benchmark_manifest.json` with config, binary, dataset, container, CUDA,
power-mode, and clock provenance. The faithful BasicEngine baseline must use
`build_legacy/slam_trainer`; the proposed Thor method uses `build_thor/`.

TUM summaries distinguish `steady_state_fps` from
`terminal_inclusive_pipeline_fps` and expose `terminal_latency_ms`. Report the
terminal-inclusive value as headline throughput. Tracking-only TUM variants do
not measure Gaussian training throughput; use the integrated protocol for that
separate result.
